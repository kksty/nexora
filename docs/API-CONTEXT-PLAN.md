# API、自建 Qwen 与容量完善计划

日期：2026-10-26（Asia/Shanghai）。用户已确认使用自建模型服务，例如 vLLM 或 Ollama；具体模型、量化、硬件和服务端窗口尚未确定。主代理负责规划、审核与验收，代码交由 `group/smart-split`（deepseek-magpie）实施。

## 当前判断

任务创建、独立执行者、共享发现、消息、共识、恢复、终端和 Web 管理已有完整主流程，适合作为单宿主开发版本继续使用。API 接入和长任务容量仍需补齐，不能据此宣称生产容量已验证。

本轮开始时的 `docs/VALIDATION.md` 记录了上一轮 208/208 自动测试通过，以及 600 条发现、300 条消息的短时增长基线；这不是本轮新功能验收，也不代表真实 Qwen、长期压测或当前部署已验证。

已确认的缺口：

- 原设置只有 `modelMaxTokens` 单次输出限制，没有用户可控的总上下文窗口、预留量与压缩阈值。
- 原检测调用 `/chat/completions`，运行时通过 DeepSeek Harness 插件；检测成功不证明实际 provider 已注册、请求协议一致或工具循环可用。
- provider/model 可以填写任意字符串，但必须验证真实运行时能路由到该服务和模型。
- 每任务模型并发默认为 2，既不是所有任务的总并发，也不是 RPM/TPM 限流、work 数量上限或费用预算。
- `state.json` 整体读写、会话和业务日志增长尚无长期容量结论；当前会话视图只读取有限尾部。

## 设置契约

下列为实施约定；如 SDK 要求调整，先同步前后端再落地，不能添加无效字段。

| 设置 | 语义与默认 |
| --- | --- |
| `modelApiProtocol` | `deepseek` / `openai-compatible`；旧配置保留 DeepSeek 行为 |
| `provider`、`model`、`baseUrl` | 保留任意服务名称和真实模型 ID，协议与显示名称分离 |
| `apiKey` | 兼容模式允许无鉴权自建服务留空；不凭空生成密钥，不把旧密钥隐式发给新服务 |
| `modelContextWindow` | 总上下文 token 数；0 表示自动。只有可信元数据才可自动决定，未知不能冒认大窗口 |
| `modelMaxTokens` | 单次输出预算；沿用既有字段，不等于总上下文 |
| `modelSafetyMarginTokens` | 额外安全预留，建议初始 2048；配合实际 tokenizer/工具格式估算 |
| `modelAutoCompactRatio` | 自动压缩触发比例，建议初始 0.75；须核实 SDK 的计算口径 |
| `modelThinkingAdapter` | `auto` / `dashscope` / `vllm` / `none`；通用模式不猜厂商参数 |
| `modelConcurrency` | 每任务在飞请求上限；自建服务建议初测 1–2 |

已知总窗口 C、输出预算 O、安全余量 M 时，客户端安全输入预算为 `C - O - M`，必须大于零。系统提示、工具描述、历史、工具结果和本轮输入都计入输入，不只计算用户消息。压缩应在接近安全输入预算前触发，工具调用与结果必须成对保留；不能简单截断 JSON 或丢弃尚未结算的工具回执。

客户端设置不能扩大服务端实际容量。vLLM 的 `--max-model-len`、模型原生支持范围及 Ollama 的服务端上下文配置都属于约束；模型列表未提供容量时必须手动确认。更改设置只对后续启动的运行时生效，已运行任务不能无提示热切换模型。

### 新旧配置兼容

旧默认 `modelMaxTokens=32000` 不能与新配置的未知窗口回退 `32768`、安全余量 `2048` 直接相加后静默启动。兼容路径必须按配置来源和行为分开：

| 场景 | 协议运行语义 | 预算与提示 |
| --- | --- | --- |
| 默认环境、旧保存文件均缺少新增字段 | 保持 DeepSeek 原路径和可用的 DeepSeek 模型元数据，不因升级缺失字段而改变协议 | 不清空用户既有输出设置，不使用 32768 冒充 DeepSeek 的已知窗口；如进入实际预算校验，应使用可信的 DeepSeek 元数据或明确标源的保守值 |
| 显式切换到 `openai-compatible` 且未声明窗口 | 使用真实 OpenAI-compatible 路由；空 Key 表示无鉴权请求 | 以 `32768` 作为明确标记为“未知、需确认服务端”的客户端回退。`modelMaxTokens + modelSafetyMarginTokens >= 32768` 时拒绝保存/启动，并提示降低输出或填写已确认窗口 |
| 用户选择未知自定义模型 | 任意模型 ID 保持动态传入，不按 Qwen 名称写死 | 不从 `/models` 缺失字段推断窗口，不宣称服务端至少有 32K；Ollama 可能仅 4K，Web 值只控制客户端预算 |

新增字段缺失的旧设置必须迁移为默认值并保留准确来源，但迁移本身不能无提示改变现有协议。设置公开状态、保存错误和切换提示必须区分 `known`、`fallback`、`requiresServerConfirmation`，并说明设置只影响后续启动的运行时。

## 自建模型初始建议

以下是调参起点，均以模型和服务端实际支持为前提，不是吞吐或显存承诺。K 按 1024 tokens 计。

| 场景 | 总上下文 | 单次输出预算 | 初始每任务并发 |
| --- | ---: | ---: | ---: |
| 首次接入、显存未知 | 32768 | 4096–8192 | 1–2 |
| 已确认支持的普通长任务 | 65536 | 8192 | 1–2，测量后再提高 |
| 大代码/长材料任务 | 131072 | 8192–16384 | 按显存和实际延迟确定 |

新接入先跑完整的一轮“模型请求 → 工具调用 → 工具结果 → 后续回答”，再测长上下文和并发。保留输出 token 余量；思考模型的推理预算及输出计数口径需按具体服务核实。Ollama 与 vLLM 的思考设置不能混用。

## 后续优先级

### P1：长期运行和多任务

1. 按实际模型后端或凭据池设置跨任务总并发、RPM/TPM 与退避协调；验收多个任务不会突破共同额度，取消与进程退出不会泄漏名额。
2. 对鉴权、模型不存在、上下文超限、429、服务异常分别反馈；固定配置错误不能无提示永久重试，暂停/等待人工处理不能被标成任务完成。
3. 展示每 work 的输入/输出 token、上下文占用、压缩事件、排队时间、首 token 延迟、重试次数及数据来源；没有服务端用量时标成估算。
4. 在独立测试环境做真实 Qwen 冒烟和数小时增长验证，覆盖模型流中断、服务重启、超时、取消、并发恢复以及压缩后工具继续运行。
5. 明确自建服务的容器访问地址，尤其 Docker Desktop 中容器访问宿主服务，不能默认容器的 localhost 一定是模型服务。

### P2：增长到一定规模后

1. 早期会话分页、业务日志归档及保留策略；保留可追溯性，清理必须显式配置。
2. 根据实测写入延迟、状态大小及恢复耗时决定是否迁移 SQLite/增量持久化，不为小基线提前重构。
3. 增加宿主 CPU/RAM/磁盘和 work 进程数的可见性，评估可选的资源接纳控制；不把资源限制当共识完成，也不擅自改变当前无固定 work 数量/费用预算的架构原则。

## 验收矩阵

- 兼容性：旧保存文件、环境回退、显式空 Key、任意模型 ID、无 `/models` 服务、不同 Base URL 形式。
- 协议：DeepSeek 原路径、OpenAI-compatible SSE、工具参数分片、多个工具调用、工具结果下一轮、reasoning/content 分离、空回复与错误响应。
- 预算：已知/未知窗口、小窗口与大输出冲突、非法数值、压缩触发及持久会话恢复；验证实际插件行为而不只断言生成文本。
- 前端：保存/回退、来源提示、校验、修改连接参数后旧结果失效、关闭/重复提交竞态。
- 容量：单任务并发与跨任务总量分开报告；采样状态大小、写/读耗时和内存；真实吞吐及最大 work 数须经指定硬件实测。
